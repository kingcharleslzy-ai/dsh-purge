# 1.6.54

## Legacy runtime link migration and error details (#79 / #77)

- When upgrading from a flat runtime to an architecture subdirectory, recognize the same installation's old runtime link, back it up, and migrate; real directories, other target links, and target files are preserved.
- If migration creation/verification fails, restore the original link; a failed restore is reported explicitly while keeping the backup, without masking permission, missing-file, or path-conflict problems.
- An apply failure shows the specific runtime reason, error code, launcher error, and recovery state; backend diagnostic details are no longer dropped, and user prompts or full configuration are not expanded.
- Restored the desktop target identification test in the default test command, and added migration, failure recovery, and real HTTP error parsing regressions.

Test evidence and boundaries are in the [maintenance record](docs/maintenance-issue-79.md). No automatic restart and no user setting changes. This fix covers the reproduced runtime layout problem; the reporter's specific environment and the preset disappearing after restart are still unconfirmed.
