# 1.7.18

## Changes

### Permission patches on by default (group switch)

- The 14 permission / approval boundary patches (`#6 #7 #8 #9 #10 #13 #14 #15 #16 #35 #51 #59 #60 #62`) no longer need `patches enable` one by one; a single `tuning.permissionPatches` switch controls them and **defaults to `true`**.
- Turning the switch off only changes plugin settings and **does not roll back immediately** what is already written to the host; the rollback happens on the next "Apply". The current session is not interrupted.
- Assertion stability: `patchEnabled()` still accepts arrays (the old form), and CLI `patches enable/disable` semantics are unchanged.

### Context management becomes its own switch

- `#18` duplicate-call reminders and `#19` tool-result trimming belong to `tuning.contextManagement`, which **defaults to `false`**.
- Old configuration with `extraPatches: [18]` / `[19]` migrates to `contextManagement: true`, the list elements are kept, and the CLI can still read them.
- Turning these two patches on removes long-session context protection and tokens keep growing — which is why the switch is off by default.

### Status page reorganization

- The main number goes back from "groups" to "patches": `60 / 75 patches written to host`, with this host's inapplicable items excluded from the denominator.
- Four states: applied / pending / not enabled / not applicable here; the last two are mutually exclusive, and "not applicable here" never counts toward any failure count.
- Added two patch-group switch cards whose hover text states the impact (which files change, whether a restart is needed, whether turning it off rolls back).
- Added a filter bar (all / pending / not enabled / not applicable here), with a status pill and description line per group; each row's status shows the reason on hover.
- The "Refresh" button became "last scan HH:MM · click to refresh" in the top right, no longer occupying the action area.
- A three-step write flow at the bottom states clearly that "the plugin will not restart for you".
- Narrow screens (≤640px) put switches and steps in one column and the four cells in 2×2; at ≤360px tables use fixed column widths and no longer break the container horizontally.

### Documentation

- `AGENTS.md` split from 517 lines / 64 KB into four files: evergreen operating notes stay in `AGENTS.md`, version and PR history in `docs/maintenance-archive.md`, troubleshooting in `docs/troubleshooting.md`, and the compatibility matrix in `docs/compatibility.md`.

## After upgrading

1. Open Purge → Status and confirm the "permission patches" switch is on.
2. Click "Apply" once (it backs up before writing).
3. Quit and reopen DSH yourself.
4. Come back; the number should be around `74 / 75`, with only the 2 "context management" patches still not enabled.

## Known limitations

- After turning the "permission patches" switch off, this page still shows those patches as "applied" until the next "Apply" performs the rollback. This is deliberate: turning a switch off must not rewrite the host on the spot.
- The 13 items not applicable on this host (including the three with missing target files, `#54 #76 #80`) never count toward the denominator and need no handling.
- The status page's "last scan" time comes from this page session and resets when the page is refreshed.

## Compatibility

- DSH Desktop `0.2.2-rc.3` (rc.1 / rc.2, `0.2.1-rc.1`, `rc.2`, `rc.3`, `rc.5` pass as well).
- Node ≥ 18.
