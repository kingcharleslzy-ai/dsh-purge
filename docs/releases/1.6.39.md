# 1.6.39

- Fix #52, where the standalone installer showed only `fetch failed` and could not locate the failure stage: it now shows the version query/archive/checksum manifest, official domain, download channel, attempt count, and underlying error code, hiding proxy credentials and signed URLs.
- Transient network errors and some temporary HTTP errors retry once first, and on continued failure it tries system curl; total attempts and wait time are capped, and system or user proxies are not changed.
- Both channels verify the official HTTPS origin and size hop by hop; certificate, SHA256, and package identity checks are preserved, and permanent errors are not retried blindly. Download or checksum failure never proceeds to installation.
- Completed real curl/TLS/CONNECT tests, fault injection, redirect boundaries, invalid certificates, truncated/oversized responses, timeouts, and settings-preservation tests; added a real GitHub download acceptance script for the selected Node/Electron runtime.

Existing prompts, settings, presets, features, or proxies are unchanged; patches are not auto-applied and DSH is not quit or restarted. The specific network fault reported in #52 still needs confirmation with new redacted logs from that reporter; a local pass is not the same as their environment being restored.

Troubleshooting and test boundaries are in [maintenance notes](https://github.com/kingcharleslzy-ai/dsh-purge/blob/master/docs/maintenance-issue-52.md).
