# 1.6.67

## Fixes

- Windows update proxy probing now prefers the read-only `reg.exe`, falling back to UTF-8 PowerShell only when needed, avoiding dependence on a PowerShell cold start every time. A failed probe states that the HTTP request has not been sent, no longer misreports the GitHub API as unavailable in general terms, and never silently switches to a direct connection.
- Transient network errors such as connection resets retry at most twice, sharing the original request timeout and redirect budget. HTTP, authentication, certificate, file size, origin, and SHA256 errors keep being reported explicitly.
- Fixed the Windows update credential file inheriting ordinary Users read permissions: a protected staging directory and file are created first, then credentials are written and atomically swapped in; reading an old file the first time tightens permissions while keeping its content unchanged. A failed overwrite keeps the old file.
- Compatible with processes started from PowerShell 7: the Windows PowerShell 5.1 helper loads only its own system modules, avoiding wrongly inherited module paths that make Get-Acl fail to load; the parent process and system environment are not modified.
- Secrets never enter PowerShell command arguments, environment variables, or logs; diagnostics for corrupt JSON no longer print credential text either. Empty secrets still do not overwrite, deletion still requires an explicit clear, and behavior preferences are still stored separately.

## Measurements and boundaries

- Real public GitHub release information requests from Mac and the Windows 11 4090 both return HTTP 200; three read-only Windows registry probes took about 9–11 ms, and the PowerShell fallback read gave matching results.
- Isolated Electron 44.7.0 on both platforms verified real HTTPS / CONNECT / SOCKS, connection resets and mid-stream aborts, total timeouts, token isolation across hosts, and SHA256 verification. All 38 Windows specific tests pass; the corresponding 33 Mac tests pass with 5 Windows-only tests explicitly skipped.
- On Windows, ACLs under a permissive parent directory, new/overwrite/old-file migration, read-only targets, real file locks and recovery after release were verified. All credentials were temporary test values.
- CI and the release flow gained the same Electron update-channel test set, and the release package keeps going through three-platform installer and regression checks.

This release changes only the general update channel and credential protection, not host patches, prompts, or auto-update preferences; the tests do not change the maintainer's official DSH settings, proxy, or protection, and do not restart automatically. An ACL is not encryption and cannot stop an administrator or a process of the same user from reading it.
