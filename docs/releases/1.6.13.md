# Purge Community 1.6.13 acceptance record

## Problem and fix

DSH Desktop 0.2.1-rc.2's tool-subagent rejects the old toolFilter argument. An old unrestricted file without an auto-management marker was correctly preserved by the updater but not migrated to the new registration protocol, so a real preset load failure occurred.

This version does not overwrite custom YAML. Before registration it saves the original agent.cordis.yml / preset.yml as private content-addressed backups with a SHA256 manifest; then, in memory, it converts a representable spawn deny policy into a native child preset and an agentPreset reference. The parent preset replaces only that one policy configuration, keeping the rest of the prompt, tool lines, depth limits, expressions, and user settings intact. The child preset inherits the configuration and excludes only the tools from the original deny list. The settings page gains an extra "Unrestricted mode · subtask" preset for delegation.

A single spawn deny list is currently supported; unknown tools, allow, multiple policies, or the meaning of an existing standalone agentPreset are not guessed. Such configuration stops with diagnostics. New installations also keep the original sub-task tool policy. The existing 83 host patches are unchanged, and patches are not auto-applied nor the app restarted.

- Real local Desktop Electron 44.7.0, DSH 0.2.1-rc.2, native Loader / AgentPresetRegistry: in an isolated home the original error of the same old preset was reproduced first, then the parent/child presets loaded successfully.

- Repeated load and uninstall tests of the real Cordis plugin found and fixed an existing disposer that was not bound to the lifecycle; parent/child declarations now dispose completely, repeated loads reuse the same backup, and the original custom file bytes are unchanged.
- Unit tests cover exact parent-configuration equivalence, prompt preservation, unknown-policy stop, corrupt-snapshot rejection, real activation error disposal, and repeated dispose.

This release does not claim full-feature Windows real-machine acceptance as complete; cross-platform file operations are checked by CI. A running DSH on this machine is not restarted automatically by the installer. Source and release packages contain no user configuration or private backups.
