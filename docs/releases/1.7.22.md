# 1.7.22

## 回退功能退役

插件自带的会话回退（输入框回退按钮 + `/purge-rewind` + `/dsh-purge/rewind` 两个接口）已移除。原因：这条路径长期有 bug，维护成本高于收益，且与宿主自身的 `/rewind` 语义重叠。

保留的兼容边界：

- **旧会话的历史仍可只读显示**：历史里已有的回退标记不会消失，也不会被当作新回退执行。
- **legacy rewind API 仍可执行回退**（这是 1.7.22 的实际行为，由 `6da239b` 明确保留）：`POST /dsh-purge/rewind` 依然能触发一次回退。只有 UI 与命令被移除。
- 宿主原生的 `/rewind` 不受影响（插件不再抢它的 UI 槽位）。

因此与回退相关的 4 条宿主补丁（#56 只藏被撤掉的一轮、#58 回退标记不进模型请求、#75 回退收回已完成任务、#77 丢弃已发送消息）保留 —— 它们在宿主原生回退被触发时仍然是修复，且不触发时不产生任何行为。

## 其它修复

- **图片投影**（#321）：回退标记不再影响图片正常渲染。
- **Windows 换包**：并发读取状态时保持路径可见（#327）；不可读的 launcher 与「文件缺失 / 二进制」区分（#322）；launcher 作业查询失败时记录原生 Win32 码（#323）。
- **桌面运行时清单**（#320）：在托管 runner 上验收 rc.5 的解包重启与字节级回滚。
- **状态页**（`c972530`）：区分「桌面 CLI 入口标记」与旧版 shim 注入，不再把两者混为一类。
