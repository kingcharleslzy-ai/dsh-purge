# 1.6.68

## Fixes

- Fixed #18/#19 being wrongly counted as "processing failures" after clicking "Apply" even though they are off by default. `disabled` now uses the same rule as the status page and selfcheck: off by choice, not a failure.
- Write errors, permission errors, required anchor mismatches, hit-count anomalies, partial application, unreadable, and unknown states keep being reported; mixed results list only the items that really failed, so disabled items do not mask anomalies.
- No feature patch, default toggle, prompt, setting, or preset was changed. #18/#19 are not turned on automatically and DSH is not restarted automatically.

## Verification

- All 8 GitHub checks on PR #124's final commit pass, including three-platform install and npm runtime verification.
- Full Mac suite 439: 421 pass, 18 platform/conditional skipped; Windows 11 4090: 413 pass, 26 platform/conditional skipped. Skipped items were not counted as passing.
- On both ends, isolated Electron 44.7.0 apply, missing-target, and partial-state specifics are 15/15 each; 26 panel tests plus UI contract, documentation, and generated bundle consistency pass.
- Negative controls with the fix removed fail the tests again; it also checks that nothing is written or backed up when disabled by default, and that mixed real errors keep the correct failure IDs.
