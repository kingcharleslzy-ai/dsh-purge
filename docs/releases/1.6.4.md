# 1.6.4

Web / Headless maintenance fix release, merging [PR #4](https://github.com/kingcharleslzy-ai/dsh-purge/pull/4) and closing [issue #3](https://github.com/kingcharleslzy-ai/dsh-purge/issues/3).

## What was fixed

- **Backup list empty after refresh**: entering or reopening the maintenance page now reads backups automatically, adds a refresh entry, and distinguishes loading, read failure, and no backups; it does not auto-select a rollback target.
- **Failures reported as success**: HTTP 200 with `ok:false` is now recognized correctly, showing backup, update, and rollback results plus partial update state separately, so "Backup created: undefined" no longer appears. After a maintenance failure it re-reads any recovery snapshot that may have been created, without auto-retrying write operations.
- **Unclear post-update load hint**: a successful install shows the version and states explicitly that the server-side DSH process must restart; refreshing the browser alone does not load the new backend.
- **Incomplete npm CLI / profile location**: maintenance, install, and read-only selfcheck share the current instance resolution logic; the npm CLI is located from the bin declared by the current package, keeping `PURGE_DSH_CLI` as an explicit override. Symlinks are supported, the correct DSH_HOME/profile is passed, other global installations are not guessed, and conflicts or uncertainty produce an explicit error.
- **Web selfcheck checking another Desktop install**: Web's app.asar check is marked "not applicable" and does not count as a layout failure; Desktop checks only its own resources directory and does not report false success when unreadable or when the target is unknown.

This release does not change permission choices, prompts, the patch table, or backup cleanup policy. Publishing does not install or restart the local DSH for the user.

## Package and upgrade

Attachments provide `dsh-purge-community-1.6.4.tgz` and `SHA256SUMS.txt`; verify before installing. Existing users can select this version from the plugin maintenance page; restart the DSH process manually after installation. Maintenance location and environment variable notes are in the [Web / Headless documentation](https://github.com/kingcharleslzy-ai/dsh-purge/blob/v1.6.4/docs/WEB-MAINTENANCE.md).

## Verification scope

- 52 backend tests pass, including 15 instance-resolution, CLI argument, and isolation tests.
- Existing panel tests plus 6 new maintenance interaction tests pass; release client assets were rebuilt.
- Build consistency, documentation version, module import, and release smoke checks pass.
- The npm CLI execution tests use a controllable entry in a temporary directory; no end-to-end acceptance of a real Linux Web service or of all host patches is claimed.
