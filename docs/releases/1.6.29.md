# 1.6.29

## Fixes

- #34: panel rollback now uses archive installation, so a bare directory cannot produce a dependency-less `link:`. After installation, dependencies and the plugin entry are verified in a new process; on failure the dependency graph, manifest, and lockfile from before the operation are restored. Existing backups stay compatible, and current prompts and settings are preserved.
- #35: unify the two plugin update request paths, supporting a GitHub token, environment proxies, and the read-only Windows static system proxy; authentication is sent only to the GitHub API and never carried cross-origin. Quota exhaustion, authentication, unavailable resources, and connection timeouts are distinguished, and Atom degradation plus stale cache state are shown.
- Fix a problem where using recursive cpSync on a Windows Node 22 link tree made the process exit natively; dependency checkpoints now copy explicitly and preserve links.
- Existing host patches, tools, and prompt policy are unchanged; the system proxy is not modified and patches are not auto-applied nor DSH restarted. The Linux install entry is handled separately.

## Acceptance

On a Windows 11 / RTX 4090 machine with a separate DSH_HOME and web profile, using the real DSH 0.2.1-rc.2 CLI: reproduced the old rollback dependency gap, restored a broken link, performed an old-snapshot rollback, re-upgraded, and verified injection-install failure with recovery to the original install, checking entry loading at each step. Existing settings and proxy configuration summaries matched. In real Electron 44.7.0, command, tool, prompt, and API registration and disposal pass; the user's DSH was not restarted.

199 automated tests: macOS 194 pass, 5 platform skipped; Windows 195 pass, 4 platform skipped. Real CONNECT/TLS tests cover proxy authentication, cross-origin token isolation, certificate validation, timeouts, and size limits; on the 4090 the release list, checksum files, and Atom requests pass.

Note: 1.6.28's directory rollback fix did not include this panel entry, so #34 is completed in this release. PAC/SOCKS is not executed; the standalone bootstrap downloader is not part of the plugin's unified network layer. Detailed boundaries in [maintenance notes](../maintenance-issues-34-35.md).
