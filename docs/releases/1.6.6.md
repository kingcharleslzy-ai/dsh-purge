# 1.6.6 install fix acceptance

This release changes only installation, archive path compatibility, and documentation; host patches, user prompts, rules, and update preferences are unchanged.

- [Three-platform CI](https://github.com/kingcharleslzy-ai/dsh-purge/actions/runs/39096529198): Linux/macOS/Windows installer and maintenance cases pass; Windows runs both PowerShell 5.1 and PowerShell 7 entry tests. Windows-specific POSIX shell tests are explicitly skipped, and Windows chmod was not treated as POSIX permission verification.
- 89 Node functional regressions, 7 panel tests, the native entry contract, build consistency, documentation version checks, and the release smoke test pass.
- Real official npm metadata: identity, version, publish time, integrity, and tarball verification for `@dsh-ops/bash-win32-x64@0.2.1` succeed; a single scope-level retry is allowed only after a simulated exact-mirror missing-version error.
- On Mac, the installed DSH Desktop's real Electron and CLI ran download verification, package migration, backup, and rollback in a separate DSH_HOME/profile; test settings were preserved and prompts changed after the backup were not overwritten by the rollback. The real DSH was not restarted and the user's actual profile was not modified.
- Windows covers real tar/Node child processes, Chinese and space-containing parent directories, argument passing, non-zero exit, download failure, and environment restore; these results are not claimed as full Windows DSH UI/host-patch acceptance.

Known boundaries: a first install from the DSH marketplace happens before the plugin loads, so this version cannot take over its error classification. Choose the official npm source or use the standalone PowerShell entry; do not disable supply-chain checks or delete lockfiles. Issue #7 stays open awaiting the original reporter's environment confirmation.

A later check of the public download entry found that a macOS temporary directory alias makes the bootstrap silently not run; use the fixed [1.6.7](1.6.7.md). The earlier isolated library-function pass did not mean the shell download entry passed, and a separate entry regression was added.
