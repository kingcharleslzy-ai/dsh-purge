# 1.6.33

Merges PR #42, adding Linux CLI/Web install support and completing cross-platform uninstall and install-failure protection.

- **Linux user-directory install**: when the system npm host is unwritable, create a user copy without sudo, without changing system directory permissions or the global npm source.
- **Switch the entry only after success**: keep the existing `~/.local/bin/dsh` when migration fails; a failed first install does not activate the new entry. If the entry is found modified by the user during migration, stop and report an error instead of overwriting the user's command.
- **Uninstall protection**: delete the plugin symlink or Windows junction itself while keeping external sources, shared packages, and external profiles; do not continue cleanup when restore or deregistration fails.
- **Path compatibility**: handle the macOS `/var` path alias and a symlinked Linux home uniformly; Linux directory boundaries stay case-sensitive.
- **Features and configuration preserved**: the host patch table, prompts, permission choices, and update preferences are unchanged, and patches are not auto-applied nor DSH restarted.

Verification includes the full three-platform test suite and release smoke, Windows PowerShell 5.1/7 with real Electron handoff, and macOS real Electron diagnostics. New real testing of the official DSH 0.2.1-rc.2 npm host in a non-root Ubuntu environment covers user-copy installation, CLI startup, plugin import, backup, rollback, and failure recovery. Linux GUI and model tasks are not fully accepted, and complete compatibility with all distributions is not claimed.
