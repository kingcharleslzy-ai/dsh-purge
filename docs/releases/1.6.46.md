# 1.6.46

Fix #67: on Windows/Electron, cleaning up dependency snapshots could delete external files a junction points at.

- Snapshots and other recursive cleanup entry points uniformly use link-following-free deletion; a symlink/junction has only the link removed, without recursing into its target. Existing permission and failure recovery logic is kept.
- Checked backup eviction, update staging/rollback directories, unpack residue, uninstall, and asset temp directories; the standalone installer and uninstall helper keep self-contained implementations, with tests preventing implementation drift.
- When an install/rollback is verified but cleanup fails, an explicit warning is returned and the residue is kept; checkpoint cleanup errors are no longer swallowed silently, and a partially cleaned snapshot is never used for automatic rollback.
- Added link protection tests, and real Windows Electron + pnpm tests for file/link dependency install, upgrade, rollback, re-upgrade, install-failure recovery, and rollback-failure recovery; link target hashes and settings bytes are checked step by step.

**Windows users on old versions: upgrade with the new standalone installer first.** Update/rollback code inside an old DSH process is not replaced immediately by downloading a new package and may still run the old cleanup logic. Do not uninstall first, clear caches, or delete lockfiles; external files already lost must be restored from a trusted source or backup — this fix does not rebuild them automatically.

Prompts, existing features, user settings, and proxies are unchanged; patches are not auto-applied nor DSH restarted. Thanks to @leaf0329 for the clear isolated reproduction and diagnosis.

Details in [impact scope, upgrade method, and acceptance record](../maintenance-issue-67.md).
