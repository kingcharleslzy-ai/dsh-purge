# 1.6.45

Fixes the #64 diagnostics problem where "apply incomplete" was falsely reported as `CMD not silently pinned (unknown)` (PR #66).

- The backend returns the host-write and configuration-restore results that the existing completion decision uses; the panel shows patch failure, host not written, configuration restore failure, CLI runtime failure, and explicit terminal check failure separately.
- When the old backend returns no specific reason, it states clearly that the reason is unknown and keeps the error state; it no longer assumes a CMD failure out of thin air, nor claims the prompt was written without grounds.
- Added 6 regression tests covering old responses, several real failures, translation, and the Apply interaction of the real React component (with HTTP boundary simulation). Simulated tests are not a substitute for verification in the reporter's environment.

This release corrects diagnostics and presentation only; it does not change completion conditions, host patches, prompts, permission configuration, or restart behavior. Publishing does not change the maintainer's local installation and settings and does not restart DSH.

The original host apply failure in #64 still needs the reporter's client release name, client and underlying DSH versions, OS, and redacted post-update error; the issue stays open. Third-party client support in #63 is still under investigation and this release does not claim compatibility. Do not upload prompts, credentials, or full configuration.

Details in the [diagnostics and compatibility record](../maintenance-issues-63-64.md).
