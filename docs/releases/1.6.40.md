# 1.6.40

- #53: added `excludePresets`, defaulting to `[]` to keep existing behavior. Matching is exact on the current preset ID, and it uniformly controls the main prompt, head/tail, capability text, boost, probe, postPrompt, and host fallback.
- An excluded session keeps its existing native persona and workspace rules; Purge sections are cleared, its own rewrites with a recorded source are reverted, and content other plugins added or changed later is preserved. User prompts and past chats are not deleted.
- The host fallback is passed the current Agent; parameterless old calls pause injection when exclusion is configured. Sub-agents judge by their own effective preset, with no global "last session" state.
- Added switching, parallel, sub-agent, full-preset, old-host LF/CRLF migration, and repeated-apply tests, plus real Cordis/SystemPrompt/request-construction runtime acceptance.

Existing settings, permission configuration, and proxies are unchanged; patches are not auto-applied and DSH is not quitted or restarted. Exclusion controls prompts only and does not revert global host patches. Old-host updates require the user to schedule applying patches and manually quit and reopen.

Configuration and test boundaries are in [maintenance notes](https://github.com/kingcharleslzy-ai/dsh-purge/blob/master/docs/maintenance-issue-53.md). Thanks to REALOIYO for the detailed report and proposal.
