# Purge Community 1.6.35

## #40: macOS manual-quit handoff and diagnostic consistency

- Fix the macOS problem where "Apply" only hinted at a restart and never scheduled an archive handoff. It now starts a standalone helper, waits for the target app and its child processes to fully exit, then verifies and preserves the original `app.asar`. It does not quit, kill, or reopen DSH.
- Archive changes while waiting, an incomplete unpacked main entry or runtime, unwritable targets, helper startup failure, and timeouts all explicitly keep a failure state. "Scheduled" is never treated as "complete".
- `host-status.handoff` and the panel's `asar_handoff` share the selected installation's record, distinguishing not scheduled, waiting for quit, complete, failed, timed out, unreadable record, and old record conflicting with a new archive. A still-sealed disk, real gaps, and unknown runtime keep showing.
- Fix the false gap where a standalone terminal session targeting Desktop still looked for `desktop-shell` among CLI/Web processes; files from another installation are never used to fill in the result.
- #71 marks "not applicable" only when the current data directory has no third-party preset family at all. A declared or existing install with missing files still reports a gap; corrupt YAML and unconfirmable configuration do not count as success.

## Verification and boundaries

Added a macOS real process-exit test and a real Electron 44.7.0 lifecycle: boot from the original archive → wait for the test app to exit on its own → verify the backup → no automatic reopen → explicit second start reads the unpacked directory; isolated settings stay byte-for-byte unchanged. Negative cases cover update conflicts, missing entry/runtime, timeout, startup failure, old locks, bad records, and lost backups.

Carried over: three-platform install/uninstall/failure rollback, Windows real Electron handoff, macOS/Windows actual Cordis diagnostics, and Linux official npm host acceptance. The patch table, Windows handoff implementation, permissions, prompts, presets, and auto-update settings are unchanged.

These tests do not replace the reporter's confirmation in a macOS 15.7.4 / DSH nightly install. The CLI still returns unknown without runtime permission evidence, and permissions should not be changed just to clear red.

## Usage and recovery

Upgrading the plugin itself does not auto-apply patches or restart. After the user clicks "Apply" in the desktop Purge panel and confirms the handoff status is "waiting for full quit", fully quit with **⌘Q**; once independent diagnostics confirm `handoff.phase=complete`, open DSH manually. Closing the window alone may not exit the process. The helper waits at most 30 minutes.

On failure, preserve state and backups first and investigate per the [#40 maintenance notes](../maintenance-issue-40.md); do not delete archives, locks, or change permissions to clear the hint. Rolling back the plugin package and restoring the host archive are two different things, and an old user configuration must not overwrite current settings.
