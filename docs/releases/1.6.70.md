# 1.6.70

This release merges #102's host location/diagnostics improvements and #128's module split plus old-settings migration fix. #127 stays open; this release does not include its Headless webServer fallback.

## Fix scope

- **Host location and diagnostics (#102)**: locate by explicit target or the current process entry, never falling back to another installation. Partial hosts keep their path, family, and read error; an unknown comparison target reports `unknown_target` instead of falsely reporting "different instance". NEXT is recognized as a separate family from package content, and CLI repair clearly distinguishes "not applicable" from "repair succeeded".
- **Module cleanup and old settings migration (#128)**: split the patch table, shared helpers, and validation modules while keeping existing exports and definitions; restored the balanced-parenthesis helper and its call constant that the split had dropped, fixing a ReferenceError in the old settings migration. Unknown rewrite templates keep being reported and user configuration is not overwritten.
- **Runtime test reliability**: the Electron ASAR test uses the raw disk interface and lets the parent process clean up directories it created after the child exits; the Windows handoff test waits for the helper to really exit and checks its exit code before reading logs, fixing an EBUSY race while keeping error assertions.

## Verification and boundaries

- All eight GitHub checks for both source commits pass, including three-platform installers, official npm host upgrade, rollback, and failure recovery. The merged release commit still runs the full repository checks and the release three-platform checks, and only uploads the installer when all succeed.
- Isolated Electron host diagnostics specifics on Mac and the Windows 4090 are 16/16; settings migration/API specifics are 8/8 each on both platforms under Node and isolated Electron. The Windows PowerShell handoff specific ran three rounds, 7/7 each.
- Those diagnostic specifics use real Electron/Cordis with temporary official/NEXT layout fixtures and **do not mean a full NEXT GUI, all host features, or old host patch migration has been accepted**. NEXT stays `qualified:false`, and real errors are not hidden.
- **The existing Defender limitation remains**: quarantine of an old-build file on the affected Windows 4090 still blocks a full upgrade/rollback. This release does not resolve that detection, nor disable protection, add exclusions, or delete files; CI passing does not mean full rollback recovery on that machine. Details in the [1.6.69 diagnostic record](https://github.com/kingcharleslzy-ai/dsh-purge/blob/v1.6.69/docs/maintenance-integrity-169.md).
- #127's public dependency provides `httpServer` while consumers need `webServer`, and the version/alias mechanism awaits the author's confirmation; it stays open and is not merged here.
