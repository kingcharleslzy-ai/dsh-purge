# 1.6.71

This release only fixes general diagnostic display and adds new-host message-turn contract tests; host patch definitions, permission behavior, prompts, presets, and user settings are unchanged.

## Fixes

- Initialize the drift and explicitly disabled counters, fixing `NaN` caused by `undefined++`.
- Group headers and the overview show anchor drift, disabled by choice, and partially applied states, while keeping pending, unknown, and real failures, without faking all-green.
- Added mixed-state counting and component rendering regressions, plus six contract tests for the official 0.2.2-rc.1 native message-turn methods. They cover empty input, two consecutive turns, explicit refusal, error callbacks, and generation failure; the tests do not call a model.

## Unresolved items and verification boundaries

- **DSH 0.2.2-rc.1 is not fully adapted**: #14, #17, #60, #62, #67, #74 keep their original definitions and unresolved status. #67's old match misses because the new try block is indented differently; a normal native turn did not reproduce missing messages, and error callbacks still report explicitly, without being silently converted into empty input.
- Two other old matches: #54's original text no longer exists in the new target; the desktop profile involved in #82 starts normally in the new isolated host. That does not mean either old patch was written, nor does it change their disk diagnostic result.
- On macOS, separate Electron and isolated profiles started the original host and a copy of the installed host, and authentication requests passed; no user third-party configuration was loaded, no model was called, and not all plugin features were verified. The earlier brief restart stall did not reproduce.
- GitHub keeps running full regressions, three-platform installers, and isolated Electron checks; those checks cannot replace acceptance of all 0.2.2-rc.1 plugin features.
- **The Defender full-rollback blockage on the affected Windows 4090 remains unresolved**; this release does not disable protection or add exclusions, and does not claim that CI passing fixed that machine. #127 stays open awaiting confirmation.

Details in the [diagnostic and test record](https://github.com/kingcharleslzy-ai/dsh-purge/blob/v1.6.71/docs/maintenance-022-diagnostics.md). The package name, install entry, and data directory are unchanged, existing settings are preserved, and DSH is not restarted automatically. The installer ships with SHA256 checksum files.
