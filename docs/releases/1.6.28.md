# 1.6.28

## Update, integrity verification, and diagnostic rollback maintenance

- Fix #28: check the actually installed version per profile; partial success keeps the failed targets and errors, only retries the failed items later, and does not commit a global version pin or update-complete marker early.
- Fix #29: the legacy upstream ZIP channel pins the commit first, then verifies each file's Git blob digest; it stops when content was modified, missing, extra files exist, or the manifest cannot be verified, and leaves the install directory untouched. SHA256SUMS verification for official TGZ stays unchanged.
- Integrate loLollipop's PR #27: a selfcheck that cannot read status no longer shows all green, rc.2/rc.10 ordering and version-stamp confusion are fixed, and brief file locks get bounded retries.
- Hardened directory rollback: preserve node_modules, .git, and file execute permissions; if moving dependencies back fails, restore the pre-rollback directory and report an explicit error. A half-installed directory from a failed fresh install stays isolated, and existing directories are never deleted on our own.
- Keep 80 host patches; #90 only removes a redundant optional annotation, with strict matching and replacement behavior unchanged. Prompts, presets, permissions, and update preferences are unchanged; host patches are not auto-applied and DSH is not auto-restarted.

## Verification and boundaries

- 191 local tests: 186 pass, 5 platform-specific skipped; UI, Electron selfcheck, documentation consistency, and the real packaging smoke pass.
- Cross-platform CI covers Linux, macOS, Windows, plus the Windows PowerShell 5.1/7 install entry and the isolated Electron lifecycle. This result is not a new round of GUI acceptance on the user's 4090 desktop.
- The real upstream commit ec69166706bed95efb6c35e225b01588f3cd9b72 passes Git tree verification for its 118 files; it verifies agreement with the commit GitHub points at, not a publisher signature or an endorsement of upstream code security. When the API is unavailable it does not degrade into skipping verification.
- #30 remains under investigation: ordinary synthesis tasks confirmed that specific system-section filtering removes project conventions / memory, but an online model-quality A/B is not finished, so this version does not claim to have resolved all capability-degradation feedback.

Thanks to [loLollipop](https://github.com/loLollipop) for the fixes, audits, and test contributions. Details in [maintenance notes](../maintenance-issues-27-30.md).

After installing an update, the user quits and reopens DSH manually when convenient. Installing does not mean the current process has loaded the new version; this release did not automatically modify the user's installation, settings, or running process.
