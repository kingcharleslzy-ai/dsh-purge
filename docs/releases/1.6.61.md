# 1.6.61

**Known limitation:** GitHub's macOS, Windows, and Linux install and runtime checks pass; however, the full install acceptance on the Windows 4090 machine was blocked by Defender quarantining the old build's existing `skills/redteam/unauth-exploit.md`, so that machine cannot be counted as accepted. That file has the same SHA256 in the old and new builds. This time no protection was disabled, no exclusion was configured, and no skill was removed; the issue remains.

This release focuses on the maintenance lock, Web sub-path requests, and the update channel, and restores native skill-directory discovery for the bundled preset.

- **#92**: full lock metadata is published atomically; a failed release keeps the mutex gate and allows the original operation to retry; ownership changes are distinguished from read failures. A cleanup error after a verified install commit preserves the scene with an explicit warning instead of triggering a wrong rollback.
- **#106**: panel requests follow the actual deployment sub-path, so status, settings, and other endpoints no longer mistakenly hit the site root.
- **PR #99**: added SOCKS5/HTTP(S) proxy and GitHub token settings used only for updates; existing environment proxies are preserved, credentials of concurrent instances are isolated, authentication details are hidden in public status, and TLS, origin, and SHA256 checks continue.
- **PR #103**: restored discovery of user, project, and bundled skill directories; presets the user modified are not overwritten, and each skill's own invocation restrictions are not ignored.
- The CLI is located before installation; prompts, settings, and existing features are preserved, and host patches are not auto-applied nor DSH restarted.

Thanks to Minggle for the update-channel contribution, Steooenwolf-666 / hans for the skill discovery contribution, and Minervaowl7 for the lock analysis.

**Not included**: the on-site resource corruption cause in #95, the handoff helper problem in #89, third-party desktop handoff in PR #102, and Cookie/header modification in PR #113. They all stay open, and unverified hosts are not marked compatible.

Test and recovery boundaries are in the [maintenance record](https://github.com/kingcharleslzy-ai/dsh-purge/blob/master/docs/maintenance-1.6.61.md).
