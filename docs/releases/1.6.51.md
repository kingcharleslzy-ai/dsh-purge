# 1.6.51

## Desktop location and install compatibility (PR #78)

- Renamed or custom-path installs are recognized by the DSH host package and CLI structure, so an ordinary Electron app is not mistaken for DSH just because app.asar exists; a corrupt preferred archive does not fall back to a stale copy.
- An explicitly selected target that is invalid stops the process rather than quietly choosing another app; mounted-volume traversal and arbitrary parent-directory scanning are removed, and multiple valid targets require an explicit choice.
- On macOS the system plutil reads XML/binary plists, rejecting missing or invalid fields, path escapes, control characters, and symlink escape, without guessing the executable name.
- The multi-architecture runtime link points at a valid directory for the current process architecture, ensuring the official CLI can load pnpm. Existing real directories, valid links, and recovery backups are preserved; conflicts, permission errors, and runtime repair failures keep showing, and a missing CLI shim no longer counts as success.
- The README's first screen credits the original author Xiaoyang / YuJunZhiXue and the restored original repository link; the original license and provenance notes are kept. Thanks to @5hux1n for the compatibility contribution.

- The project display name is unified as **dsh-purge Community**; the package name `dsh-purge-community`, internal plugin ID, configuration, and backup paths stay unchanged.

## Tests and scope

All 8 GitHub checks for PR #78 pass. Before merge, the full automated suite had 328 passing, 0 failures, 12 platform or conditional skips; isolated Electron on Mac ARM64 and Windows 11 x64 each completed 5 groups of real official CLI/pnpm install, old-version migration, upgrade, rollback, re-upgrade, and failure recovery. pnpm in the architecture directory actually executed, and the official configuration files checked did not change. Detailed evidence in the [acceptance record](../pr78-runtime-integrity.md).

This release's changes are limited to general location, installation, and runtime loading; no existing features are removed, user prompts, settings, or presets are not modified, and DSH is not auto-restarted. Real measurements do not mean all third-party DSH variants, cross-architecture simulations, and marketplace UI are covered. After installing, the user fully quits and reopens DSH when convenient.
