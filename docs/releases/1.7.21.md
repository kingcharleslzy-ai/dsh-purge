# 1.7.21

## 这一版主要修什么

上两版把拒绝重试与审计标签理顺了；这一版处理的是**补丁口径与宿主交互**的旧账。

### 补丁条数与状态

- 逐条诊断与旧版的分组摘要以前会互相"推算"条数，导致同一页出现两套数字（#261 / #266）。现在以逐条诊断为准，分组只做聚合显示。
- `skipped` 与「本端不适用」在所有接口（状态页、`/dsh-purge/status`、CLI `selfcheck`）口径一致。
- 补丁 #71 改为**按文件证据**判定（#260），不再依赖单个标记位：文件里有对应改动才算生效，部分改动记为未就绪。

### 与宿主的交互

- `/purge-rewind` 改成直接注册（#302），不再和宿主的 `/rewind` 抢同一个 UI 槽位。
- 管理类 HTTP 路由要求 Host owner 准入，避免同机其它进程直接调用管理接口。

### 稳定性（#318）

- 状态视图刷新后保持一致，不再出现"刷新一次数字变一次"。
- 修回 exec 相关封装的 promise 契约。
- 发布元数据的 TLS 请求失败可重试（临时故障不再直接判为失败）。
- Electron 诊断夹具加鉴权，同时保留匿名拒绝用例。
- Windows 验收改在 GitHub 托管 VM 上用官方 DSH + Chrome 跑。

## 已知限制

- 宿主改成 `app.asar` 内嵌布局时，按文件定位的补丁可能报 `target_file_missing`（跟踪于 issue #257）。这一版没有改变这个前提，状态页会如实显示「本端不适用 / 文件缺失」，不会假装已应用。
- 更新检查的列表路径仍受 `per_page=20` 与 2 MiB 上限约束；失败时走 `/releases/latest` 元数据兜底（PR #225），只报版本号、不给安装包。


## 升级

装好后重启 DSH。宿主补丁若因布局变化显示未应用，请看状态页的逐条诊断，不要直接点应用后当作已生效。
