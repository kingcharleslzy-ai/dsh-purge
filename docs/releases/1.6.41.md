# 1.6.41

Fixes the auto-update area always showing an old version "waiting for restart" and blocking later automatic installs.

- Status is verified using the version loaded in the current process against the disk-installed version of the current profile; both cross-version upgrades and rollbacks recognize superseded old records.
- A disk handoff is no longer mistaken for the running process having loaded it: when a restart is still needed, both versions are shown and the automatic install is not repeated.
- Missing files, wrong package identity, read failures, partial install failures, and rollback failures stay visible; a successful update check or "no new version" does not erase an install failure.
- Automatic checking, automatic installation, interval, prompts, rules, and other existing settings are preserved; host patches are not changed and nothing is auto-applied or restarted.
- Added cross-version status, failure recovery, and panel plus real DSH install/rollback tests. Details in [maintenance notes](../maintenance-update-state.md).

If an old process is already stuck on residual state, install this version manually from the maintenance page, then quit and reopen yourself once; the new version reconciles old records automatically. No need to delete settings or toggle update switches.
