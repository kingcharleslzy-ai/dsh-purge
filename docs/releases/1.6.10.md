# 1.6.10 Windows re-update after unpacking acceptance

After 1.6.9's desktop handoff and settings API tests passed, a recheck of the public install entry found a problem in another stage: installing again after a handoff, the CLI could not find pnpm under app/runtime. 1.6.9 was immediately moved to prerelease and stopped being promoted as a stable update; published tags are not rewritten.

## Root cause and fix

A Windows junction's relative target is resolved against the process working directory, so the previous `..\runtime` could point to the wrong place. It is now an absolute resources/runtime in the same installation; the old bad link is renamed and kept, and neither the link target nor the directory contents are deleted. It stops on an existing real directory or a different valid runtime link conflict, and does not overwrite on its own.

The fix is used both for host unpacking and by the standalone installer. The installer checks the link before calling the current instance's unpack CLI; if the pnpm runtime is unavailable before a handoff, the helper keeps the original archive and reports an error. An updater already broken in an old version cannot load the new logic, so install 1.6.10 through the README's standalone Windows install entry.

## Verified

- Windows 11, real official DSH Desktop 0.2.1-rc.2, separate app, profile, and user-data-dir.
- With the real archive already moved aside and the GUI reloaded, 1.6.10 was installed from 1.6.9; the old bad link was preserved, the native Desktop CLI's pnpm call succeeded, and prompt and configuration SHA256 stayed unchanged.
- On that unpacked host, a real snapshot, rollback to 1.6.8, and re-upgrade to 1.6.10 were completed; the current prompt and content added after the backup were both preserved. The snapshot verified immediately, later old snapshots were cleaned per the existing retention policy, and user retention settings were not changed for the test.
- 16 Windows specific tests pass, including handoff after the real Electron parent exits, refusing a handoff when the runtime is missing, absolute junctions, preserving bad links, installer current-instance location, and native settings compatibility.
- 103 macOS main tests pass with 5 Windows-conditional tests skipped; panel and Electron ASAR regressions are preserved.

1.6.9's #9, #10, and PR #11 fixes remain in place; see the corresponding acceptance records. UU mouse automation is unstable, so no claim is made that every Windows control, account login, or arbitrary model output was manually verified. The user's default DSH data, proxy, and image-generation service were not modified. The plugin still does not restart automatically by default; test restarts happened only in a Windows isolated copy the user authorized.
