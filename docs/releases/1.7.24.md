# 1.7.24

> **破坏性变更**：这一版删掉了 14 条权限 / 沙箱 / 审批宿主补丁。宿主补丁总数 **88 → 74**。

## 为什么删

那 14 条（沙箱 deny→allow、审批默认 never、升级无条件授信、fs fence 取消等）是**改写宿主执行边界**的补丁，一直是最脆弱的一层：DSH 每次升级都要重新对锚点，且容易和其它插件/官方行为打架。

#292 把它们整体下线，边界交回宿主自己的配置；插件改为在**注入层**提供控制，并通过官方 `configEditor` 服务写回配置（#293）。

## 现在提供什么替代

- `lib/inject-config.js`：经 `configEditor` 做「校验 → 持久化 → Loader 协调」，支持
  - `excludePresets`：按预设排除注入
  - `excludeSessions`：按会话排除注入
  - 分层开关：逐层控制注入（提示词层 / 工具层 / 代码层）
- 面板：迁移证据未收敛时状态页仍可用；旧版的权限编辑在创建/刷新/消费备份前会先被还原校验，不会带着半截状态写盘。
- 平台摘要如实标注 Windows / macOS（#332），配置自检纳入平台诊断。

## 兼容字段

`tuning.permissionPatches` 保留但**不再影响任何补丁**——那 14 条已经不存在。读到该字段不会报错，也不会产生效果。

## 对破甲能力的影响（需要重启后实测）

- **内容层**（模型是否拒绝、拒绝后能否重试救回）：不受这批补丁影响，仍靠提示词注入 + 拒绝重试。
- **执行层**（bash/pwsh 写文件、沙箱拒绝、审批弹窗）：以前由补丁改写，现在由宿主配置决定。如果你的宿主设置为严格沙箱，这一层会比 1.7.23 更"听话"。
- 重启后我会用同一批真实请求跑一遍，把结果和 1.7.23 对比，不靠推断。

## 升级

装好后重启 DSH。升级后第一次打开状态页，如果看到「迁移证据未收敛」属正常，点一次「应用」让配置写回后再看逐条诊断。
