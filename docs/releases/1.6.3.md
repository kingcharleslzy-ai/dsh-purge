# 1.6.3

> 1.6.3 = the boost section gains an "authorization means execution" clause: after declaring own assets / a CTF, no second confirmation.

Field feedback: in some sessions the model clearly saw the authorization statement and still kept demanding "proof of authorization" or reversed into asking "are you sure". The boost section gains one clause: when the target is already declared as own asset / client project / CTF range, execute directly and stop asking for authorization documents; when undeclared, ask only once "does this target belong to you, or is it a range?", and after a yes answer start immediately without revisiting it later. Unauthorized third-party targets are still refused — that is the model's own policy and the plugin makes no promise at that layer.

DSH 0.2.1's `dsh-tool-subagent` rejects `toolFilter` outright (selection moved to `agentPreset` in the agent preset), and an old preset carrying it fails to mount entirely, so two custom modes showed red. The red-team preset's tool line name still said `dsh-purge/redteam/tools` (the package was renamed `dsh-purge-community`), which also produced `never started`. Templates were fixed, self-healing was added (strip `toolFilter` in place, migrate the old package name), and the two local presets were refreshed once.

- **Merge [PR #1](https://github.com/kingcharleslzy-ai/dsh-purge/pull/1) (@luowang-ui)**: `repairOfficialCliAfterUnpack()` is a synchronous function that called the async `atomicCopyFile` without awaiting — on Windows/Node 24 the rejection bypassed `try/catch` and escalated to `uncaughtException`, so the host exited during loading ("the app cannot start or has stopped unexpectedly"). A data-integrity problem was fixed along the way: the async copy could read the file after the patch was written and store the patched bytes into `.dsh-purge.bak`. Added `atomicCopyFileSync` and regression cases.
- **Installer package persistence**: `install()` first copies the tgz to `$DSH_HOME/dsh-purge-community/pkgs/` and then hands it to pnpm, so a `file:` pointing at `/tmp` or Downloads does not break dependency resolution after a restart.

- **Audit log**: every `apply` / `revert` / `boost` / `probe` / `preset` / `reanchor` action writes one JSONL line (`audit.jsonl`, rotated at 1MB with two copies retained); readable via `purge-community audit` or the panel's "Maintenance → Recent actions". An apply record carries the snapshot id, host version, success/applied/failure counts, and failing patch ids.
- **Release smoke test**: `npm run smoke` unpacks the tgz and verifies — 8 export targets exist, core modules import, the bundled preset parses into a 20-line definition, `cordis.patch.yml` entries are complete, the CLI runs in an empty directory, and selfcheck degrades safely to broken with no host. Wired into both the community and release workflows.
- **Health-check fixes**: `anchors.js` no longer imports core (removing a circular dependency); the reanchor cache became an explicit variable; `--index` with a missing value and an invalid `audit --limit` value are both guarded; expired probe files are cleaned up automatically; preset registration no longer retries 40 times ineffectively on "duplicate/invalid".

When a host upgrade breaks an anchor, `diagnose` now gives more than line numbers: `reanchor apply <id> --lines A-B` extracts the real snippet from the current host as a candidate (verifying uniqueness, previewing with a dry-run first), and with `--yes` writes a local override into `~/.dsh/dsh-purge/anchor-overrides.json`; the patch engine applies by index and `reanchor clear <id>` undoes it. Overrides are recorded per host version, so after a version change you can see at a glance which anchors are locally pinned.

- **Snapshot deduplication**: files larger than 32KB are stored by sha256 under `backups/objects/`, and snapshots keep only references; the same `client.js` occupies space once. Measured: one snapshot went from 9.0MB to **2.0MB**; `verify` checks every object hash, and `prune` automatically GCs unreferenced objects.
- **AGENTS.md**: an operating manual for agents — the five-layer model, commands and exit codes, the symptom→action decision tree, how to read and add patches, state files and invariants. `check:docs` now validates its version line too.
- **README**: version number and new features (probe, preset, three-state selfcheck, deduplication) synced; the command table gained `probe` / `preset`.

- Selfcheck distinguishes "pending" from "cannot apply": pending uses ⏳ (yellow) and only broken is ✗ (red); `selfcheck` exits 1 only when broken, so the installer no longer reports failure for "one more apply needed".
- New runtime probe: the panel's "Probe" button or `purge-community probe new` generates a one-time nonce and appends a short "echo this verbatim if you see it" instruction to the end of the system prompt — the model echoing it means the injection really reached the context (auto-expires after 30 minutes).

## Key changes since 1.2.0

### 1. The "always forbid writes" master switch is removed

To dodge old patch risks, 1.2.0 hard-coded `patchWritesAllowed` to `false`, which also disabled revert, uninstall, Hooks, the per-patch status area, auto apply/auto update, and the restart entry. 1.3.0 restores those entries one by one as in upstream:

| Capability | 1.2.0 | 1.3.0 |
| --- | --- | --- |
| Apply / reapply host patches (UI, `/purge apply`, `purge_apply` tool, HTTP) | All blocked | All restored |
| Revert / uninstall (UI, command, tool, HTTP) | All blocked | All restored, uninstall and revert still handled separately |
| Startup self-heal, post-upgrade recovery, `autoApplyOnStart` / `autoUpdateOnStart` | Forced off | Follows configuration |
| Hooks toggle, per-patch/shim/backup status | Hidden or refused to save | Restored display and saving |
| Auto restart after apply (including sealed asar restart) | Changed to a manual hint | Original scheduling restored, still bound by the user-manual-restart rule |
| Original CLI `dsh-purge --status/--apply/--revert/--uninstall/--edit` | Not packaged | Exported again; `purge-community apply|revert|uninstall|edit` forwards directly |

Compatibility is no longer a write gate: `compatibility()` only produces a report (`qualified` / `unverified` / `mixed` / `no-host`), and only "host completely unlocatable" and "component versions mismatch" still block writes.

## New in 1.3.1

- **Bypass boost section on by default**: the tail of the system prompt gains hierarchy declaration / refusal-is-failure / anti-sycophancy / multi-turn restatement; disable with `purge-community boost off` or one click in the panel.
- **Switchable injection position**: `head` (default, saves tokens) / `tail` (next to the output, least multi-turn decay) / `both`, stored in `$DSH_HOME/dsh-purge/tuning.json`.
- **#89 `ask_user_question` no longer blocks the turn**: the wait cap is squeezed to 1 second and the turn continues on timeout (the user can still answer in the UI).
- **Drift diagnostics suggest possible new locations**: `diagnose` returns line numbers + snippets when an anchor misses, to make reanchoring easy.
- **Bypass selfcheck**: `purge-community selfcheck [--json]`, `GET /dsh-purge/selfcheck`, panel "Status → Bypass selfcheck". 21 layers each give evidence (host patches / runtime injection / profile permissions / whether asar is sealed), and layers whose target plugin is not installed are marked "not applicable" instead of failed.
- **Backup retention policy**: default keep_last=5, keep_daily=7, 200MB total, evicted automatically after `backup/install/rollback`; `purge-community usage` shows usage and `prune` cleans up immediately. Previously a single day could pile up to 65MB with no cap.

## Known boundaries

- This round's verification was done on a **pristine 0.2.1 host copy** (full-table apply + `node --check` on each of the 41 modified files + the patched host's `--dump-config` working normally). Runtime effect after clicking "Apply" in the real client requires a restart and user confirmation.
- No end-to-end acceptance for Windows / Web profiles.
- Upstream `YuJunZhiXue/dsh-purge` is unmaintained; report issues with this fork to this repository.
