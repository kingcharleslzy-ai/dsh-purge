# 1.6.83

- `unauth-exploit` now explains how to verify command execution through an existing authorized test entry. It generates a new challenge each time and provides POSIX and Windows PowerShell commands separately. When only a file write is possible, it is recorded as file write access.
- A new bundled `scripts/exec-proof.mjs` generates the challenge on the operator side and checks the raw output. It does not connect to the target and does not authenticate the execution source; the entry and exit status must still be checked. The old document's WebShell and persistence command examples were not re-added.
- The skill's commands were run in isolated environments on Mac and the Windows 4090; correct responses pass, while verbatim echoes, previous-turn responses, mixed output, empty output, and static text are all rejected. Host patches, user settings, presets, and the install/rollback flow were not changed.

When migrating from much older versions on Windows, Defender may still block a full snapshot of the old package's files; this release does not fix or bypass that limitation. See the [1.6.82 migration notes](https://github.com/kingcharleslzy-ai/dsh-purge/releases/tag/v1.6.82).
