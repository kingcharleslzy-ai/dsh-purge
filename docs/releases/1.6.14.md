# Purge Community 1.6.14 acceptance record

## Fix scope

- #20: the new inode created by an atomic replacement did not inherit rwx permissions, turning a shell launcher from 0755 into 0644. A shared atomic-files module was extracted: synchronous/asynchronous replacement preserves old permissions, and copy and rollback preserve the source file's permissions. Unique temporary names avoid concurrent conflicts; failures in write, chmod, or rename clean up the temporary file and throw.
- A failed backup of the official CLI now blocks replacement, and read/write errors set report.ok=false. Existing backups are not overwritten; when a recognized old launcher lacks every execute bit, the matching execute bits are added from the existing read bits, keeping its content and read/write permissions.
- #19: added host-status and the status endpoint's host_layout, read-only distinguishing the target disk layout from the current service's startup entry; the old panel's wording that inferred "the current process still loads the archive" from the archive's presence is corrected. Diagnostics return no full command lines or environment variables.

## Boundaries of the #19 conclusion

Reproducible in an isolated directory: with app.asar and an unpacked directory both present, the existing sealedAsarHandoff returns null on the Web surface while the Desktop surface returns that archive. This matches the Web context clue in the report, but cannot prove the reporter's actual full call chain. The test did not start the quit/handoff helper or move the archive.

The same disk layout can also correspond to archive_entry, unpacked_entry, or unknown_runtime; after the archive is moved away, the original process entry can still point at the archive. The panel and Agent must now look at evidence separately and must not treat a write count as proof of runtime loading.

**#19 stays open; this version does not claim the full handoff flow is fixed.** Existing handoff helpers, restart scheduling, host patches, prompts, preset policy, and update preferences are all unchanged.
