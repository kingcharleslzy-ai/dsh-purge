# 1.6.9 Windows host handoff and settings compatibility acceptance

A later recheck of the public package found that installing again after unpacking can fail because a Windows relative junction points to the wrong place. 1.6.9 was moved to prerelease; use [1.6.10](1.6.10.md). The tests actually completed at the time are kept below, and are not equivalent to the whole install chain passing.

Environment: Windows 11 Pro build 26300, signature-valid official DSH Desktop 0.2.1-rc.2, Electron 44.7.0. An isolated app copy, separate profile, and user-data-dir were used; account credentials were not copied, and the existing image-generation service, network proxy, and default DSH data directory were not changed.

## Fixes

- #10 / PR #11: after writing disk patches, use a waiting helper with a handshake, logs, timeouts, and archive verification. It does not quit the host on a timer, kill the app, or restart automatically. After exit it keeps the single original archive backup and verifies SHA256 before recording completion.
- Additional real-machine finding: Electron's Windows detached PowerShell can exit 0 without executing the script. A short broker starts a separate helper and records broker and helper startup errors separately. Regression confirms the helper can finish the handoff after the Electron-launched process exits.
- #9: the modern settings service keeps native describe/replace and does not expose legacy register. Upgrades remove only the known old shim, keeping native settings events and user data; unknown modifications stop with diagnostics, and old hosts keep the compatibility interface.
- Fixed a Windows file-replacement failure caused by backup descriptors not being closed; a failed backup stops writes. The actual code version is verified after install, and a rollback directory link bug that made a re-upgrade load the old package is fixed.
- The user notice carries its dialog styles independently; user confirmation stays in the user's hands. Disk patch state and current process load state are labelled separately.

## Real-machine results

1. The official Desktop runtime completed installation, backup, rollback to 1.6.8, and re-upgrade to 1.6.9. The current prompt, prompt content added after the rollback, and profile configuration stayed unchanged.
2. Per-file backup, complete patch application, revert, and re-apply against the real host gave zero failures; the settings module after revert matched the original bytes.
3. The new helper was triggered from the actual desktop host's app API, confirming waiting_for_quit, the helper inside the desktop session, and the host still responding. After shutting down the isolated copy per test authorization, the helper completed the handoff, the archive backup SHA256 matched, and nothing reopened automatically. After reopening, the API returned sealed=false, handoff=complete, plugin 1.6.9.
4. After reload, the host layer, runtime injection registration layer, and layout layer selfchecks are all ok. The isolated profile follows host default permissions, so the permission-choice configuration layer is not marked green; to keep configuration unchanged, its permissions were not rewritten for the selfcheck. Selfcheck state is not verification of arbitrary model output.
5. A standalone test profile was started with the real Settings, ConfigEditor, and Loader; settings were read three times, then saved and read back successfully, and legacy register does not exist.
6. 12 Windows PowerShell 5.1 specific tests pass; 6 PowerShell 7 handoff tests pass. There is also a regression for handoff after the real Electron parent process exits. 100 macOS main tests pass with 4 Windows-conditional tests skipped, and 9 UI component tests plus the real Electron ASAR selfcheck pass.

## Verification boundaries

This record covers the install, update recovery, host patch handoff, native settings, and status API above. The UU desktop can display the app, but automated mouse input is unstable, so it cannot be claimed that every Windows page control received manual click acceptance; account login flows, the refusal rate of arbitrary models, and all third-party plugin combinations were not tested. Old/new settings compatibility, helper failure branches, and page behavior have separate automated regressions.

Default behavior still does not restart DSH automatically. A test restart explicitly authorized by the user is an acceptance operation and does not change the plugin's default policy. Host addresses, real paths, configuration bodies, and account information do not enter release packages or public evidence.
