# 1.6.42

Fixes content preservation, stream cancellation, and settings logging issues reproduced during PR review.

- Prompt sectioning recognizes only the old uppercase marker that sits outside a code fence on its own line; identical text in the body, quotes, indented code, and code fences is preserved. Recognition is not widened to new case forms.
- When the user cancels a normal answer, the close propagates upstream so the connection stops being held; a single iterator is closed only once.
- Stream diagnostics record text, tool_call, reasoning_only, or empty only after the source ends; late errors and user cancellation are recorded separately. They represent transport outcomes, not a correct answer or task success; new diagnostics store no response bodies or raw error text.
- Settings changes are recorded uniformly at the write entry point as actual changes, with no duplicate entries when nothing changed; unknown configuration is kept but stays out of the audit. A failed save is not recorded as success; invalid field values are not written to the log verbatim.
- Corrected the retry toggle explanation: it is read on the next request; the UI reload requirement for rewind is kept, without falsely reporting immediate effect.

Thanks to loLollipop for the leads in PRs #59, #60, and #61. This release is a standalone reliability fix and does not integrate #58–#61 as a batch; those PRs stay open, and the parts not adopted remain for further discussion. Existing detection rules, retry wording, defaults, and host patches are unchanged.

User settings, prompt files, and installation are not modified, and patches are not auto-applied nor DSH restarted. Test scope and unadopted items are in [maintenance notes](docs/maintenance-pr-58-61.md).
