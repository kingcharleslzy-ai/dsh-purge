# 1.6.66

## Fixes

- Fixed the panel being unable to locate the current host when some Electron desktop shells start with only `--updated`. Read-only diagnostics are limited to the current process's package-identity-verified resources directory; install and write target selection is unchanged.
- Use Electron's actual app entry as evidence. For unknown, read failure, or cross-instance cases, "handoff complete" is no longer falsely shown; genuinely missing components keep being reported.
- Windows handoff no longer treats every move failure (backup conflicts, permissions) as "waiting for unlock". Sharing/lock conflicts keep waiting; other failures show the original reason and error code, preserving the original archive and existing backups.
- The maintenance page and CLI use the same basis for host version diagnostics. A standalone CLI without an instance gives an explicit explanation and does not treat "not located" as "plugin not installed".

## Verification and scope

- All GitHub checks for PR #121 pass, including Mac, Windows, and Linux install plus official npm host upgrade, rollback, and failure recovery.
- Local regressions: 409 passing, 13 platform/optional-conditional skips; 26 UI tests pass.
- Real measurements with isolated Electron 44.7.0 on Mac and Windows 11: a desktop shell started with only `--updated` recognizes its own host and actual entry; installer target selection is unchanged.
- On Windows, a real file lock returns error 32 and the handoff works normally after release; an existing backup target returns error 183, fails explicitly, and keeps both files. The handoff helper keeps waiting and completes after the launcher exits.
- Prompts, settings, existing features, and update preferences are unchanged; this release is not installed into the maintainer's official DSH and does not restart automatically.

#118 stays open: what was reproduced and fixed is an error-classification problem, which cannot be used to conclude the reporter's specific stuck cause. Their handoff state, error details, and helper logs are still needed. The #119 fix is limited to host diagnostics and does not mean the NEXT desktop release mentioned in #102 is fully compatible.
