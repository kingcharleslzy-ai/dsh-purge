# 1.6.48

Fixes the maintenance flow for custom prompt protection and alias installs.

- **#72**: no longer judges a body as default content by template keywords inside it. Explicitly custom, hand-edited, and unknown-origin bodies are preserved; startup sync, apply, and install share the decision. A read failure does not overwrite the file. Confirmed default upgrades and explicit restore-to-default remain.
- **#74**: version reconciliation recognizes the standard install name and the `dsh-purge` alias and verifies the real package identity; YAML dependencies are read from the actual package location. Fixed backup, upgrade, and rollback for alias installs; rollback keeps the original dependency name, entry, and later user settings.
- Missing, corrupt, or ambiguous multiple copies are not hidden, and update errors are not deleted to pretend the problem is fixed. Host patches, injection content, permissions, proxies, and update preferences are unchanged, and nothing restarts automatically.

An old-version reconciliation error may block automatic installation, so upgrade in place with the new standalone installer instead of uninstalling and reinstalling. Private bodies already overwritten by an old version must be restored from the user's drafts or backups; this release cannot rebuild them automatically. Rolling back to the old version brings its old defects back too.

Verification and applicability boundaries are in [maintenance notes](../maintenance-issues-72-74.md).
