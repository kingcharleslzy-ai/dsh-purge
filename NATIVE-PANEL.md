# Purge native sidebar build

The `native-panel` branch of this fork maintains the separate `dsh-purge-panel` UI plugin. `master` tracks upstream state. The original author is YuJunZhiXue/dsh-purge; copyright and license notices remain in the repository root and in the UI package license.

## Install and update

The official `dsh-purge` and `dsh-purge-panel` are separate packages. The former keeps the original functionality; the latter registers the Purge tab in the right sidebar, the settings layout, and the styles that hide the old entry points. Updating the official package does not overwrite the standalone UI files. Do not use it together with earlier builds that embedded the UI directly into `dsh-purge@1.1.71-local.*`.

```sh
cd packages/purge-panel
npm ci --ignore-scripts --legacy-peer-deps
npm run build
npm test
npm pack --ignore-scripts
# Use the CLI installed with your current DSH installation:
dsh plugin --profile desktop add ./dsh-purge-panel-1.1.0.tgz
```

Install and enable the official Purge package first, then install the UI package. Open the right sidebar and choose `+ → Purge`. Disabling the UI package restores the official entry points without deleting the original settings.

## Follow upstream

```sh
git fetch upstream
git switch native-panel
git merge upstream/master
cd packages/purge-panel
npm ci --ignore-scripts --legacy-peer-deps
npm run build
npm test
```

After merging, check whether the official `/dsh-purge/*` APIs and the `.dshp-launch`, `.dshp-hero-chip`, and `.dshp-tab-chip` entry selectors have changed. After verifying against the new version, update compatibility notes and tests, then package the UI. New settings added upstream do not appear automatically in the standalone UI and must be adapted explicitly.

The current verified compatibility baseline is official Purge 1.1.71. Other versions show compatibility notices; if the API is unavailable, the UI also shows a notice. The UI uses the `dshpp-` style prefix and its own locale to avoid mixing with upstream styles. It does not modify scheduled tasks or loader patches in the official installation files.

## Verification

`npm test` verifies native tab registration, draft preservation when switching categories, no input overwrite on refresh, no automatic save when viewing pages, rules for hiding old entry points, version-change handling, and service error notices. Migration was verified on DSH Desktop: after restoring the official package to its original state, the standalone right-sidebar UI still loaded and the original prompt files were unchanged.

CI only tests and packages; it does not publish to npm, GitHub Releases, or the plugin marketplace. Any official distribution requires a separate decision.
