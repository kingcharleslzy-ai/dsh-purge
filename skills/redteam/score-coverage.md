# 得分点覆盖与路径选择

> 先跑 `redteam_score_list` 拿当前靶标的实际 code/上限/档位，并读每条返回的 `evidence_need`（判定标准）与 `evidence_proof`（自证材料）；本技能只给"怎么识别、先打哪、要什么证据"，不替代工具返回。
> 原则：**先算分值 ÷ 投入**，再决定打哪条；服务器权限是进内网的跳板，不是唯一目标。

## 0. 快速分型表

| 资产长什么样 | 优先 code | 第一入口 | 关键证据 |
| --- | --- | --- | --- |
| 域名注册/DNS/子域接管 | `domain-control` | 注册商、DNS 服务商、子域 CNAME | 域名控制台截图、解析记录、WHOIS |
| 摄像头/打印机/WiFi/PC/手机/大屏 | `terminal-access` | 默认口令、管理后台、MDM | 设备归属证明（页面/资产标签/单位名称） |
| Linux/Windows 主机、WebShell | `server-host` | RCE/上传/弱口令/提权 | 命令回显、WebShell 连接、权限 |
| MySQL/Redis/MSSQL/ES/Mongo | `db-credential` | 未授权、弱口令、SQLi | 连接成功、库/表、数据量 |
| OA/邮箱/ERP/业务后台 | `web-app` | 登录面、默认口令、越权 | 浏览器登录成功、后台页面、账号档位 |

| 堡垒机/域控/SSO/终端管理 | `central-system` | 管理后台、凭据复用 | 管理员页面、托管节点 20%（最多 20 台） |
| Hadoop/Hive/Spark/ES/Kafka | `bigdata-system` | 管理端、未授权 API | 管理员权限、数据量 ≥5 亿条/1TB |
| VPN/防火墙/路由器/交换机/网闸 | `netdev` | 管理口、默认口令、SNMP、CVE | 路由表/连接量截图；重定向 +200、植入 +1000 |
| SCADA/HMI/PLC/车联网/智能制造 | `iiot` | 管理后台、暴露的工控协议 | 管理员后台、托管设备数 |
| K8S/OpenShift/云控制台/AK-SK | `cloud-platform` | API Server、控制台、metadata | 管理员操作证明；节点 <100 按 web-app |
| 摄像头/门禁/物联网管控平台 | `iot-platform` | 平台后台、默认口令、API | 平台控制、连接点数；打入核心网 +5000 |
| WAF/IPS/IDS/审计设备 | `secdev` | 管理口、默认口令、CVE | 管理员权限（非集权类） |
| FTP/NAS/OSS/企业网盘 | `file-storage` | 账号/AK-SK、默认口令（匿名不算权限） | 登录/调用成功、账号档位 |
| 模型智能体/skill/Agent 平台 | `ai-agent` | 管理端、提示词注入、工具滥用 | 可操作 agent 的证据、控制深度 |
| Jupyter/Kubeflow/MLflow/Ray/知识库 | `model-compute` | 未授权、弱口令、API | 系统管理权限；知识库/超大数据 ×2 |
| 模型权重/训练数据/推理服务 | `model-data` | 管理端、对象存储、API | 管理员权限；无知识库翻倍 |
| 算力平台/卡池 | `computepower-admin` / `computepower-cards` | 平台后台、调度 API | 管理员 500；10 分/卡 |
| 隔离内网/网闸/物理隔离 | `boundary-logical|strong|physical` | 隧道/跳板/隔离设备 | 入口区/落点区/隔离设备/靶标内网资产四问 |
| 供应商/云服务运维通道 | `boundary-supply` | 供应商 frp/VPN/运维平台 | 用户确认范围 + 进入主防单位内网 |

## 1. 域名控制（domain-control）

- 识别：目标主域/子域的注册商、DNS 托管、CNAME、证书、WHOIS。
- 路径：注册商/ DNS 控制台弱口令或被盗凭据 → 改解析/加子域；子域接管（CNAME 指向未认领的云资源）；DNS zone transfer；证书签发滥用。
- 证据：控制台截图、解析记录 before/after、WHOIS/备案主体；一级 50 / 二级 20，按域名类型给分。
- 注意：只改可控记录并留证据，不做破坏性解析；不要碰非目标域。

## 2. 终端（terminal-access）

- 识别：打印机、WiFi 路由器、摄像头、电子大屏、PC/Pad/手机、MDM/终端管理后台。
- 路径：默认口令/未授权管理页 → 设备控制；钓鱼/终端管理后台 → 批量终端；AD/ MDM 托管节点。
- 证据：设备页面 + 与目标单位的关系（资产标签、单位名称、页面落款）；打印机/WiFi 5 分/台，PC/Pad/手机/摄像头/大屏 10 分/台；批量给 3 张代表图即可。
- 注意：不要批量锁死设备；不要触碰与业务生产直接相关的控制指令。

## 3. 网络设备（netdev）

- 识别：VPN/SSL-VPN、防火墙、路由器、交换机、网闸、光闸、摆渡机。
- 路径：管理口默认/弱口令、SNMP 社区串、已知 CVE、配置文件泄露；拿到权限后看路由表/策略/连接量。
- 证据（G7）：路由表、策略配置、连接量截图；普通 100 / 管理员 200；网络重定向/业务劫持 +200；植入远控并成功后续攻击 +1000。
- 注意：改路由/策略前先备份并记录原值；不做断网式操作。

## 4. 云管理平台（cloud-platform）

- 识别：K8S/OpenShift、云控制台、PaaS 管理端、AK/SK、metadata 服务。
- 路径：API Server 未授权/弱口令、控制台弱口令、AK/SK 泄露、SSRF 打 metadata、CI/CD 凭据。
- 证据：管理员操作（新增节点/改权限）截图；管理员 500；云上主机/容器 10 分/台；节点 <100 按 `web-app`，节点不计分。
- 注意：AK/SK 批量控制默认只算节点分，除非能证明管理员权限。

## 5. 物联网 / 工业互联网（iot-platform / iiot / iot-corenet）

- 识别：摄像头/NVR/门禁/传感器平台、SCADA/HMI/PLC、车联网/智能制造/远程诊断。
- 路径：平台默认口令/未授权 API、设备固件/协议暴露、厂商运维通道；从端点设备横向进核心网。
- 证据：平台控制台、连接点数、设备清单；平台 200，连接点 10/台；经端点打入核心网并控制业务生产 +5000（单独记一条）。
- 注意：不要操作生产控制指令；先在只读页面取证。

## 6. 安全设备（secdev）

- 识别：WAF/IPS/IDS/审计/日志平台（非集权类）。
- 路径：管理口默认口令、CVE、API 未授权；拿到后看策略/日志/资产发现能力。
- 证据：管理员页面、设备型号/权限；管理员 200，上限 1000。
- 注意：集权类（堡垒机/域控/SSO/终端管理）走 `central-system`，不要混。

## 7. 文件存储（file-storage）

- 识别：FTP、SMB/NAS、对象存储（OSS/S3/MinIO）、企业网盘。
- 路径：账号/AK-SK、默认口令、后台登录；匿名列举/读写只记漏洞或数据，不算存储系统权限。
- 证据：登录/调用成功、账号档位、文件清单；管理员 50 / 普通 10；数据单独计分（G2）。

## 8. 模型 / 算力（ai-agent / model-compute / model-data / computepower-*）

- 识别：Agent/skill 平台、Jupyter/Kubeflow/MLflow/Ray、训练数据/知识库、模型权重、算力平台/卡池。
- 路径：管理端弱口令/未授权、API 未授权、提示词注入/工具滥用、对象存储 AK/SK、调度 API。
- 证据：控制/操作 agent 的截图、系统管理权限、知识库/数据量、卡数；`ai-agent` 100–500；`model-compute`/`model-data` 500；知识库/超 1 亿条或 10TB ×2；算力管理员 500，10 分/卡。
- 注意：不要真的投毒/破坏训练；用只读或可回滚操作取证。

## 9. 边界突破（boundary-*）

记分前必须回答四问（写进 `boundary` 对象：entry_zone/target_zone/isolation/target_asset；supply 加 scope_confirmed=true）：

1. 入口区：互联网/DMZ/办公/生产/隔离？
2. 落点区：隧道/跳板实际到哪个区？
3. 跨了什么隔离：防火墙/网闸/光闸/物理隔离/多网卡跳板？证据？
4. 实际访问到的靶标内网资产：IP:端口 + 回显/协议交互。

同区或四问缺一 → 只记 `internal`。逻辑隔离 1000、强隔离 10000、物理隔离 30000；`boundary-supply` 还要求用户确认供应商/云服务在范围内，且证明进入主防单位内网（不是只进供应商内网）。

## 10. 通用规则速查

- **G1 取高**：同一系统/主机/数据库只按最高权限计一次；先记低档后提权，用 `points` 记高档。
- **G2 数据单独计分**：邮件/业务/数据资产按重要程度另记；`evidence` 写实际条数/大小。三要素等敏感信息 **≥1 万条**优先；只取证明所需样本，不拖全库。
- **G3 上限**：每条 rule 有上限，warning 是停止信号，换条/换资产。
- **G4 按台/个**：终端、云节点、物联连接点、算力卡按数量累加。
- **G5 翻倍**：大数据系统 ≥5 亿条/1TB 才按大数据；G5 翻倍 ≥1 亿条/10TB 或知识库，记分时传 `data_scale`。
- **G6 IPv6**：IPv6 成果 ×3，记分传 `ip_version=6`。
- **G7 证明**：边界要隔离设备/能访问内网截图；网络设备要路由表/连接量；终端要归属证明；集权托管节点要 20%（最多 20 台）。
- **T2/T3 不计分**：旁站/同 C 段/共享托管等弱相关资产，只有升级为 T0/T1（同 ICP/证书/注册人/合同证据）或用户明确确认后才按对应 code 记；T3 永不记分。
- **G8 兜底**：规则没覆盖的系统，用 `redteam_score_point_save` 新增自建点，写清判定口径。

## 11. 选择顺序（作战优先，不只看分值）

1. **P0 能进内网**：能 RCE / 命令执行 / 上传 / 反序列化，且落点能当跳板（边界/边缘、VPN/防火墙/堡垒机/运维平台、双网卡、对外中间件/上传点）；先拿服务器权限、建隧道、实测进内网。
2. **P1 敏感数据**：互联网/内网未授权接口、已拿账号可访问的接口、数据库/备份，能导出姓名/身份证/手机号等三要素 **≥1 万条**；只取证明所需样本并统计总量。
3. 可直接登录的集权/大数据/业务系统（500–1000 分）。
4. 网络设备/云平台/物联网/安全设备（200–500 分）。
5. 服务器主机/数据库/文件存储（10–50 分；不能进内网时再作为主目标）。
6. 域名/终端（10–50 分，批量或单点）。
7. 边界突破（1000–30000 分，但必须四问齐全，不能靠“隧道可达”硬凑）。

> P0/P1 是**投入顺序**，不是改写分值；具体分值/上限仍以 `redteam_score_list` 为准。

> 一个资产命中多个 code 时，按“最高权限/最高分值 + 最强证据”记一条；不要为了凑分在同一服务上刷同类成果。
