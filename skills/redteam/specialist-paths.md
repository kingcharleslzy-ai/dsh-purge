# 专项资产路径选择

## 原则

- **先分型，再选路径**：资产类型决定入口、工具、证据和风险；
- 先查 `score-coverage` 的对应 code 和证据要求，再决定投入；
- 同一资产可能有多个得分点，但只按实际拿到的最高权限计分；
- 任何路径都先满足授权、范围和 OPSEC 约束；不做破坏性动作；
- 拿不到就写清卡点和替代路径，不要用 Web 扫描结果冒充专项成果。

## 快速分型与入口

| 资产形态 | 优先确认 | 典型入口/线索 | 关键证据 |
| --- | --- | --- | --- |
| VPN / SSL VPN / VDI / 远程办公 | 产品与版本、认证方式、MFA、公网端口 | 登录门户、客户端下载页、版本公告、配置泄露 | 登录成功/管理面截图、隧道实际可达 |
| Exchange / OWA / 邮件网关 | 版本、OWA/ECP、Autodiscover、MAPI | OWA 登录面、ECP、版本漏洞、凭据复用 | 邮箱/管理面访问、邮件数据证明 |
| 防火墙 / 路由器 / 交换机 / 网闸 | 厂商、型号、固件、管理口、SNMP | HTTPS/SSH/Telnet/SNMP 管理面、配置备份 | 设备管理页、路由表/ACL、配置证据 |
| AD / 域控 / SSO / 堡垒机 / 终端管理 | 域名、DC、LDAP、Kerberos、CA、SCCM/Intune | 域枚举、认证服务、委派/ACL、证书服务、管理后台 | 域管/节点控制、策略/证书/托管证据 |
| 云平台 / 对象存储 / K8s | 云厂商、账号、IAM、Bucket、API Server | 控制台、AK/SK、metadata、容器 API、CI/CD | 控制台权限、桶/对象、集群/节点证据 |
| 数据库 / 大数据 | 类型、端口、认证、连接串来源 | 配置泄露、弱口令、未授权、SQLi、linked server | 登录成功、库表/数据量、查询回显 |
| 文件存储 / 备份 / NAS | 协议、共享权限、匿名访问、备份任务 | SMB/NFS/FTP/对象存储/备份管理端 | 目录/桶清单、文件内容、管理权限 |
| 摄像头 / 打印机 / 门禁 / IoT | 厂商、管理端、默认口令、协议 | 管理页面、ONVIF/RTSP、默认账号 | 设备控制页、视频/配置/归属证明 |
| 工控 / SCADA / PLC | 协议、HMI、工程站、隔离方式 | 管理端、工程软件、暴露协议 | 只读状态/组态证据；禁止影响生产 |
| AI / Agent / 模型平台 | 管理端、工具调用、知识库、API | 控制台、API、Agent 工具链、提示词注入 | 可操作 Agent/知识库/模型数据证据 |
| 供应链 / MSP / 运维外包 | 关系证据、运维通道、云服务 | 供应商入口、远程运维、CI/CD、共享账号 | 用户确认范围 + 进入主防单位内网证据 |

## AD / 身份专项（高优先级）

按“发现 → 验证 → 证据”推进，不直接上破坏性动作：

1. 域/林/DC/CA/信任关系与 DNS；
2. 账号、组、ACL、委派、GPO、服务账号；
3. 认证面：Kerberos、LDAP、SMB、WinRM、RDP、Exchange；
4. 证书/ADCS、SCCM/Intune、vCenter/ESXi 等集权系统；
5. 拿到入口后先证明“能管理什么”，再决定横向路径；
6. 证据：域管/节点/策略/证书/托管对象 + 实际操作回显。

优先找“一个入口控制一片”的集权面，不要只扫单台主机。

## 边界与网络设备专项

- 先确认设备归属和是否在授权范围；
- 管理面优先：HTTPS/SSH/SNMP/配置备份；
- 版本、默认口令、配置泄露、ACL/路由；
- 证明“设备可控”比“端口开放”重要；
- 不重启、不改路由、不锁管理账号；变更前备份并记录回滚值。

## 云 / K8s 专项

- 云：控制台/IAM/AK-SK/对象存储/metadata/函数/CI-CD；
- K8s：API Server、kubelet、Dashboard、RBAC、Secret、CI/CD；
- 只读优先，证明权限边界；
- 不删资源、不创建后门、不导出超出证明需要的数据。

## 失败后的替代路径

- 外网 Web 全失败 → 转 VPN/VDI/Exchange/供应链/身份面；
- 单台主机拿不到 → 找集权系统/双网卡/备份/运维通道；
- AD 拿不到域管 → 找 ACL/委派/ADCS/Exchange/SCCM 的间接路径；
- 云控制台拿不到 → 找 AK/SK、CI/CD、metadata、对象存储；
- 所有路径都失败 → 写清失败信号和建议补的资源，不要重复扫。

## 输出要求

每条成果必须能回答：

1. 这是什么类型的资产？
2. 从哪个入口拿到什么权限？
3. 证据是什么（页面/命令/报文/截图）？
4. 是否在授权范围内？
5. 是否已独立复核？
6. 对应哪个得分 code，是否已落库？
